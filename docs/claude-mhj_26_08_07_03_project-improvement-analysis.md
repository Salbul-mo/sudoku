## 2. CI 부재 (심각도: 높음)

**근거**: `.github/`, `.gitlab-ci.yml` 등 자동화 설정이 **하나도 없다**
(`ls -a`로 확인). 이 세션에서 수행한 모든 검증 — JS 284개, Python 88개,
대비 게이트, 브라우저 검증 — 은 전부 사람이 수동으로 실행한 것이다.

**영향**: 테스트가 충실하게 갖춰져 있는데도 그 가치가 "실행하는 것을
기억했는가"에 달려 있다. 이 세션만 해도 팔레트 교체 때 고정값 테스트 3개가
깨졌는데, 수동 실행을 건너뛰었다면 그대로 푸시됐을 것이다. 특히 Cloudflare는
푸시하면 자동 배포되므로, **테스트가 깨진 상태로 배포될 수 있는 구조**다.

**제안**: GitHub Actions 워크플로 하나로 충분하다.

```yaml
# 푸시/PR 시: node --test "tests/js/*.test.mjs"
#             node tools/check-contrast.mjs
#             node tools/codex-mhj_26_08_02_05_build_pages.mjs --check
#             (선택) venv 없이 pip install -r requirements.txt 후 manage.py test
```

Node는 외부 의존성이 없으므로 `actions/setup-node`만으로 즉시 돌아간다.
가장 적은 비용으로 가장 큰 이득을 주는 항목이라 1순위로 둔다.

## 3. HTML 페이지 보안 헤더 부재 (심각도: 높음)

**근거**: `game/static/`에 `_routes.json`은 있으나 **`_headers` 파일이 없다**.
보안 헤더를 설정하는 코드는 `functions/api/new-puzzle.js`의 API 응답
(`X-Content-Type-Options: nosniff` 등)뿐이고, **HTML 문서 자체에는 CSP도
`X-Frame-Options`도 없다** (`index.html`과 함수 코드 전수 검색으로 확인).

**영향**: 이 앱은 인증도 서버 상태도 없어 피해 범위가 제한적이지만,
- 클릭재킹 방어가 없다 (임의 사이트가 iframe으로 감쌀 수 있음)
- XSS가 발생했을 때의 2차 방어선이 없다

두 번째 항목이 특히 아깝다. 이 코드베이스는 이미 **`innerHTML`을 일절 쓰지
않는다는 불변식을 소스 수준 테스트로 강제**하고 있다(`board-view.js`,
`app.js`, `touch-controls.js` 등에 대한 테스트 존재). CSP는 그 방어를
브라우저 차원에서 한 겹 더 받쳐주는데, 정작 그게 빠져 있다.

**제안**: `game/static/_headers` 추가. 이 앱은 인라인 스크립트도 외부
리소스도 쓰지 않으므로 매우 엄격한 정책을 부작용 없이 걸 수 있다.

```
/*
  Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
  X-Frame-Options: DENY
  Referrer-Policy: no-referrer
```

**주의**: 적용 후 반드시 `wrangler dev`에서 콘솔 CSP 위반이 없는지 확인해야
한다. 위 정책은 정적 분석으로 도출한 것이고 런타임 검증은 아직 하지 않았다.

## 4. 같은 도메인의 구현이 둘 (심각도: 중간)

**근거**: 스도쿠 엔진이 두 벌 존재한다.

| | Python | JavaScript |
|---|---|---|
| 위치 | `game/sudoku/` | `functions/_lib/sudoku/` |
| 엔진 규모 | 853줄 (dlx/solver/generator/spec) | 690줄 |
| 테스트 | 약 1,000줄, 88개 통과 | 통과 |
| 배포 여부 | **아니오** (로컬 개발/롤백 전용) | **예** |

**양방향으로 어긋나 있다** (코드 확인):

- JS에만 있음: `givens` 22..60 지정, best-of-30 재시도
- Python에만 있음: 12x12 / 16x16 지원, `easy/medium/hard` 난이도 이름
- Django의 `/api/new-puzzle/`은 **`?givens=`를 무시하고 항상 32개를 반환**한다

**영향**: 로컬 Django로 개발하면 최신 기능이 동작하지 않는다. 이는 의도된
결정이었고("Cloudflare를 쓸 것이므로 Django는 건드리지 않는다") 앱이 깨지지도
않지만, 결과적으로 **로컬 개발 환경에서는 검증할 수 없는 기능이 생겼다**.
실제로 직전 기능은 `wrangler dev`가 아니면 검증이 불가능했다.

또한 두 구현이 같은 답을 내는지 **검증하는 장치가 없다** (JS 테스트가 Python
엔진을 참조하는 곳이 없고, 구조상 참조할 수도 없다).

**선택지** (판단이 필요한 지점이라 결론을 내리지 않는다):

- **A. Python을 참조 구현으로 명시하고 유지** — 두 구현이 같은 퍼즐 집합을
  만드는지 확인하는 교차 검증 스크립트를 추가한다. 알고리즘 회귀를 잡는
  안전망이 생기지만 유지 비용이 계속 든다.
- **B. Python을 아카이브** — `game/sudoku/`를 히스토리 참조로 명시하고 로컬
  개발도 `wrangler dev`로 통일한다. 2,374줄의 유지 부담이 사라지지만 롤백
  경로를 잃는다.
- **C. 현상 유지 + 문서화** — 최소 비용. 다만 "둘이 다르다"는 사실이 문서에
  남아야 한다.

어느 쪽이든 **지금처럼 아무 표시 없이 갈라진 채 두는 것**이 가장 나쁘다.

## 6. Worker/브라우저 경계의 상수 중복 (심각도: 낮음)

**근거**: `GIVENS_MIN/MAX/DEFAULT`가 두 곳에 존재한다 —
`functions/_lib/sudoku/..._generator.js`와
`game/static/game/js/core/claude-mhj_26_08_07_01_givens.js`.

불가피하다. Cloudflare Pages는 `functions/`를 브라우저에 서빙하지 않으므로
프런트엔드가 Worker 코드를 import할 수 없다.

**현재 완화 조치**: `tests/js/claude-mhj_26_08_07_02_givens-constants.test.mjs`가
양쪽을 모두 import해 값이 일치하는지 단언한다(Node는 두 파일 모두 읽을 수 있다).

**남은 위험**: 같은 패턴이 반복될 것이다. `DIM`/`CELLS`는 이미
`core/spec.js`와 Worker의 spec 양쪽에 존재한다. 지금은 값이 같지만 이를
검증하는 테스트는 없다.

**제안**: 경계를 넘는 상수가 셋째로 늘어나는 시점에, 브라우저와 Worker가
모두 import할 수 있는 공유 디렉터리(예: `shared/`)를 두고 빌드 시 복사하는
방식을 검토한다. 지금 당장은 **기존 `DIM`/`CELLS` 중복에도 동일한 일치
테스트를 확장하는 것**만으로 충분하다(비용 몇 줄).

## 7. fake DOM 한계 (심각도: 낮음)

**근거**: `tests/js/helpers/fake-dom.mjs`는 의도적으로 최소 구현이며(jsdom
도입 금지가 명시된 결정), 다음이 지원되지 않는다.

- `dataset` 쓰기가 속성에 반영되지 않음 → `[data-action="newGame"]` 조회 불가
- 클래스 셀렉터 미지원 → `.visually-hidden` 조회 불가
- 자손 결합자 미지원 → `[role="dialog"] button` 조회 불가

**실제로 겪은 일**: 직전 기능의 통합 테스트에서 `[data-action="newGame"]`
조회가 `undefined`를 반환했고, 버튼 텍스트와 `[aria-live]` 속성으로 우회해야
했다.

**영향**: 테스트가 실제 셀렉터와 다른 방식으로 요소를 찾게 되므로, **실제
브라우저에서만 드러나는 셀렉터 불일치를 놓칠 수 있다**. 이 세션에서 브라우저
검증이 단위 테스트가 놓친 결함을 여러 번 잡아낸 이력이 이를 뒷받침한다.

**제안**: jsdom 도입은 기존 결정에 반하므로 권하지 않는다. 대신
`dataset` 설정이 `getAttribute("data-*")`에도 반영되도록 fake DOM을 조금만
보강하면(수십 줄), 가장 흔한 불일치 원인이 사라진다.

## 8. 의존성 버전이 산문에만 존재 (심각도: 낮음)

**근거**: `package.json`도 lockfile도 없다. wrangler 버전은 배포 문서의
`npx --yes wrangler@4.118.0 ...` 명령 **문자열 안에만** 존재한다.

의도된 설계이며(로컬 의존성 없이 유지) 실제로 잘 작동해 왔다. 다만 버전이
문서 산문에 있어 CI(2절)를 도입하면 같은 문자열을 워크플로에도 적어야 하고,
두 곳이 어긋날 수 있다.

**제안**: CI 도입 시 wrangler 버전을 워크플로 env 변수 한 곳에 두고 문서가
그것을 참조하도록 한다. `package.json` 도입까지는 불필요하다.
